控制台与遥操的显式控制权限

SDK 源码保留在真机。prepare_sdk.py 读取当前源码，逐个核对锚点，在独立 work 目录保存候选、原件、SHA256 和完整差异；不覆盖已有修改。
build_candidate.py 复用真机现有编译和链接参数生成独立二进制，不替换正在运行的文件。--skip-existing 仅用于同一份未改动候选的中断续编。
install_candidate.py 要求真实反馈确认双臂失能、底盘停稳、升降无活动会话且停稳、无录制和遥操作动作，再备份并安装经过检查的候选。

行为
- 生产启动配置启用 explicit_control_source，初始选择 console。选择存放在协调程序中，刷新网页、连接或断开 Quest 不会改变选择。
- 控制台模式下，协调程序不发布机械臂目标，不响应 Quest 的 X 启动。关节目标、底盘网页会话和升降位置会话仍需各自显式操作。
- 遥操模式下，控制台运动入口在网页、HTTP 代理和设备接口拒绝；原遥操仍需显式启用，并通过已有反馈、输入中立与故障检查。
- 切换只变更控制来源，不使能、不回零、不移动、不撤销机械臂保持。存在动作或底盘/升降活动会话时拒绝交权，需先停止并释放。
- 保留 B、停车、停止关节动作和原有故障保护。权限模式不改变速度、关节限位、升降行程、硬件零点、URDF 或相机外参。
- 安装时让协调程序随机器启动，启动后只选择控制台，不使能或运动。关闭“遥操作程序”服务也会关闭权限协调；控制台会明确显示该服务未就绪，不能把这个状态显示为 Quest 已占用。

验证入口
test_authority.py：实际候选协调程序、底盘和机械臂 mock 驱动，隔离 ROS 域97，覆盖连接、长按X、显式选择、设备接口互斥和 HTTP 互斥。
test_lift_authority.py：复用 SDK 的升降 PTY 固件模拟，不打开真实串口，覆盖权限选择对升降位置会话的约束。
test_browser.py：实际 DOM 与页内模拟 API，覆盖三个控制入口、显式切换与无自动运动。base_console/test_console_browser.py 保留既有底盘网页回归。

未启用 explicit_control_source 的旧 SDK 启动入口保留 legacy 行为，便于既有独立测试和历史启动配置兼容。

遥操网页就绪修复：patch_teleop_ui.py 只生成/安装 app.js 候选，不重启任何设备服务。
移除遗留50Hz网页门槛，按现行SDK的新鲜输入、至少3样本及手柄追踪条件显示启用按钮；后台100毫秒中立窗口与原运动保护不变。
顶部显示手柄数据中断、具体手柄追踪无效、等待显式启用或遥操作已启用，避免把追踪保护停止误认为权限问题。
test_browser.py 额外覆盖38Hz可用、无效追踪与过期输入仍禁止启动、恢复输入不自动运动。真机更新时保留当前控制权和转矩保持。
