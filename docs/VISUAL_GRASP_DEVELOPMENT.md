## 目标与基本原则

目标是根据头部相机识别的箱沿，让真实夹爪钩子移动到箱沿上方，再向下插入、闭合并验证抓箱。
开发不能只看当前代码。必须同时检查真机 SDK、用户提供的结构资源、URDF、相机外参和已有实测记录。
当前代码没有用到某项资源，不等于资源没有提供；接口尚未接通，不等于真机没有该能力。

SDK 提供真机关节角度；URDF 提供关节链、夹爪安装关系和几何。两者正确对应后，应能计算完整夹爪和钩尖的位姿。
不应在使用这些已有信息之前就要求重新测量全部结构或重新标定。

## 正确理解关节反馈与零位

- 当前 SDK q[16] 的已知排列为右臂索引0～6、右夹爪7、左臂8～14、左夹爪15。操作前仍需核对真机接口。“J8”存在编号歧义，不能直接当作腕关节。
- 使用实测反馈角度计算当前姿态，不能拿 nominal_target 或已发送目标代替实际位置。
- 第七关节不在零位本身不是问题。正确的模型必须在非零角度下也能算对夹爪姿态。
- 发送零目标并确认实际到零，可以观察 SDK 零位对应的实物姿态；它不会自动证明该姿态与 URDF 定义一致，也不是计算当前姿态的前置步骤。
- 先核对编号、单位、方向、参考零位和变换实现。没有实测依据不得强制置零、反号、套历史固定偏移或改 URDF 来贴合一幅图。

## 完整坐标链必须追到底

关节侧：`SDK 实测关节角 → 对应机械臂链 → 腕端 → URDF 夹爪安装链 → 手指/钩尖`。

视觉侧：`头部 RGB-D 与正确内参 → 箱沿/抓取目标 → 已选外参及对应升降补偿 → 与钩尖相同的坐标系`。

1. claw1.3 已包含夹爪安装和结构，先检查程序是否完整使用了它们，是否漏算或重复应用固定变换。
2. 腕端 link7、SDK EE 控制点、夹爪基座、钩尖不是可随意互换的名称。逐一核对所代表的真实位置。
3. 若 URDF 没有显式钩尖 frame，可以根据已提供几何建立明确的局部点或 frame；不能因此笼统声称夹爪几何缺失。
4. 若钩尖随开合移动，检查 SDK 夹爪反馈如何对应 URDF 手指关节。电机角度不能直接作为米制 prismatic 位移；先查 SDK 与已有资料中是否已有映射，再判断是否需要测量。
5. 检查相机与关节/升降数据的配对、图像预处理后的内参和坐标定义。叠图错位可能来自相机侧，不能单凭它断定机械臂零位错误。
6. 升降补偿必须在明确的坐标定义下计算，不能把编码器高度、URDF 升降零位和距地高度混用，也不能重复补偿。
7. 左右臂分别使用对应的 SDK 根与腕端链。已有检查发现左侧推导的 CAD 整机注册直接用于右侧会产生约120 mm模型平移差异；这不等于实物右肩安装错了120 mm。

## 排查顺序与证据要求

1. 盘点本次使用的 SDK 部署、URDF/网格、外参、箱体资源及来源指纹，读取现有测量记录。
2. 获取或使用已保存的真机实测反馈，明确实时/回放、时间与对应图像；追踪其进入运动学的全过程。
3. 检查代码接入和完整坐标链，用同一组角度比较模型输出，排除漏变换、重复变换、错索引、错单位、错模型版本。
4. 比较完整夹爪与实物，区分相机投影误差、结构/安装参数差异和反馈定义差异。单图拟合不能替代多姿态验证。
5. 只有发现具体参数缺失或不一致后，才提出针对性测量或标定，说明缺哪一个量、已有资源为何不能给出以及如何验证。
6. 对应关系确认后，逐步验证箱沿上方对位、竖直插入、闭合及试抬。关节端点到位不等于钩尖沿直线运动，闭合目标成功也不等于已抓牢箱子。

“URDF 与 SDK 运动学一致”指同一组角度下两套计算的腕端结果一致；不能简写成“URDF 与真机实物已对齐”。
同样，尚未验收不能反过来表述为资源不存在、结构一定错误或必须重新标定。
每次报告分别说明资源是否存在、代码是否使用、软件验证结果、真机观测和剩余具体问题。
