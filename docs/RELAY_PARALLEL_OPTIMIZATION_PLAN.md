# 拆码垛并行优化方案

日期：2026-09-29。状态：设计方案，尚未实施本文新增并行功能。

## 1. 目标与范围

同时优化 A 拆垛、B 码垛，以及 A/B 经交接台衔接的流水作业。主要方法是把姿态准备重叠到已有行驶时间中，减少停车调整和等待，不以整体提高速度上限作为首选。

分别统计任务仿真用时和实际墙钟用时。动作并行可以缩短任务仿真用时，但增加规划计算也可能拖慢仿真推进，最终以两项指标共同判断收益。

保留当前抓取和码放规则：

- A 双手夹稳后以直立箱体为目标；当前持箱倾角保护阈值为 10°，允许小幅倾斜，不要求持续精细扶正。单端辅助取箱仍可有必要的倾斜。
- B 搬运保持直立；有同层邻箱时，先对齐纵向位置，放置阶段允许同侧倾斜。双爪均参与下降，邻箱同侧优先接近支撑，确认支撑后同侧先松爪、退出，再由异侧爪完成横向推入和松爪。
- 有同层邻箱的放置不改回底盘推入；无同层邻箱的分支沿用现有暂放、推箱规则。
- 不放宽关节限位、夹持接触和支撑检查。A 的 10° 阈值不应用到 B，也不作为规划目标倾角。

## 2. 当前代码与可优化点

| 当前实现 | 事实与优化空间 |
|---|---|
| `scripts/whole_body_control.py: WholeBodyIK.solve` | 升降与左右臂联合求解；当前调用基本固定底盘位姿，不是三套执行器依次单独运动。 |
| `scripts/relay_runtime.py: hands / plan_hands` | 已有上身完整路径预检查和关节同步执行，可用于并行前确认可达性。 |
| `move_and_prepare / dock` | 已支持部分导航与姿态准备交错执行。需要复用、补充准入条件，不能直接重复启动两个会修改同一执行器的动作。 |
| `navigate` | 当前 A 进入直立持箱模式后和 B 持箱时通常保持上身姿态。旧的持箱姿态调整分支不能直接视为新的并行方案。 |
| `run_a` | 去源垛时已有收臂准备并行；撤出源垛、行驶到通道、调整交接持箱姿态仍有串行动作。 |
| `run_b` | 靠近交接台已有接箱准备并行；去目标垛的高度准备、放箱后的收臂返回有优化空间。 |
| `workers / HandoffCoordinator` | A/B 已能交错推进任务；交接区由 A、B、推箱机构互斥占用，并用物理状态确认提交。优化重点是减少等待，不是重新实现双机器人并发。 |

当前最新 A 倾角阈值已放宽且单元回归通过，但尚无该配置下完整 18 箱通过记录。此前 A 严格 3° 检查曾在抬升时触发停机。需要先取得当前配置的可比基线，不能把未完成的任务当作优化成功基线。

## 3. A 拆垛阶段安排

| 阶段 | 建议并行动作 | 开始和结束条件 |
|---|---|---|
| 空载前往源垛 | 底盘行驶，同时升降和双臂进入紧凑的取箱预备姿态 | 离开交接台干涉范围后开始；到源垛侧通道时完成主要调整。 |
| 最终靠近、辅助取箱 | 底盘稳定，按现有顺序接近、夹取、接入另一只手、试抬 | 不把底盘行驶叠加到单手夹持或邻箱接触动作。 |
| 持箱撤出源垛 | 先保持夹持姿态向外退 | 用实际箱体和手臂包络确认已离开源垛，不能只看底盘位置或固定计时。 |
| 开阔通道运箱 | 底盘直线行驶，同时升降和双臂调整到交接预备高度与收箱位置 | 双侧夹持有效、无转弯、整段联合运动可行、包络不碰环境。 |
| 进入交接台 | 停止大幅上身调整，底盘完成最后对位 | 持箱准备已完成且取得交接区操作权；随后放箱、松爪、撤爪。 |
| 放箱后返回 | 清出交接区后，返回行驶与收臂、下一箱高度预置重叠 | 先确认夹爪脱离箱体和台面；只有物理退出完成才释放交接区。 |

优先把 `run_a` 中通道直线行驶与 `prepare_handoff_carry` 的可行部分重叠。源垛附近的额外退让和 IK 备用路径保留，不为并行省掉必要的清障动作。

## 4. B 码垛阶段安排

| 阶段 | 建议并行动作 | 开始和结束条件 |
|---|---|---|
| 空载返回交接台 | 底盘行驶，同时收臂并准备接箱高度 | 先退出目标垛及邻箱范围；可提前到外部等待点，不提前闯入交接区。 |
| 接箱与撤离交接台 | 保留夹持确认和清台顺序 | 双侧夹持、试抬和撤离完成后，才开放持箱并行。 |
| 运往目标垛 | 直线行驶，同时调整到目标层预备高度 | 以已预留目标槽位规划；预备高度应满足整段通道和目标垛接近净空。 |
| 目标垛侧通道 | 可重叠小幅高度和持箱位置调整 | 在进入邻箱范围前完成主要升降；上身未准备好则在通道等待。 |
| 最终放置 | 底盘稳定，升降和双臂按既有放置策略协调运动 | 纵向先对齐；有邻箱时保留同侧优先支撑、松爪、撤爪，再异侧横向推入的依赖顺序。 |
| 退出并返回 | 夹爪清出干涉范围后，底盘离开与收臂同时执行 | 不得在手还位于箱沿内或压住箱壁时直接撤底盘。 |

高层码垛不应一出交接台就升到最高处。先在较低且可行的持箱高度通过转弯，在目标垛前的开阔直线段完成升高；具体高度由路径净空与 IK 可达性确定。

## 5. A/B 流水作业与交接调度

目标时序是：B 运输、码放第 n 箱时，A 取第 n+1 箱；交接台空闲且目标缓冲位可用时，A 可完成下一箱入台；B 放完返回后接走已准备好的箱子。

```mermaid
flowchart LR
    A[A 取下一箱并运往交接区] --> W[交接区外等待点]
    W --> D[取得操作权并放箱撤离]
    D --> H[必要时执行台面移箱]
    H --> B[B 接箱并清出交接区]
    B --> P[B 运输和码垛]
    D --> A
    P --> R[B 返回外部等待点]
    R --> B
```

图中台面移箱仅在当前箱子路由需要时执行，保留现有源位置到交接槽位的映射。图示循环表示可重叠工作，不表示交接动作可绕过互锁。

保留交接台全局互锁：A 入台、B 取箱、推箱机构动作之间仍互斥。槽位预留、箱子逻辑归属、实际物理占用分别管理，不能以“计划离开”代替“实际离开”。

减少占锁等待的方法：先在区域外完成可独立进行的姿态准备，确认可进场后再申请操作权；动作结束后，满足现有稳定、清台与推箱机构归位条件立即提交。未来若要缩小区域锁，必须另行证明两侧完整运动包络不重叠，本轮不实施。

交接台满时，A 在不阻塞 B 的等待点等待；B 缺箱时可返回外部等待点并完成空载准备。不得为了增加“并行率”而多取一箱、越过现有缓存容量，或改变目标垛的支撑依赖顺序。

## 6. 运动执行设计

### 6.1 首轮沿用分层控制

底盘仍由导航控制；升降和双臂仍由联合 IK 控制。先增加受约束的同步调度，不立即引入底盘加双臂的全自由度联合优化。

以底盘坐标系表达运输中的箱体预备姿态。若底盘世界变换为 `T_WB(t)`，箱体相对底盘的预备轨迹为 `T_BC(t)`，则箱体世界目标为 `T_WC(t) = T_WB(t) × T_BC(t)`，双手目标由该箱体目标与已有夹持变换生成。

不能把底盘起点处的世界系手部目标固定下来，让底盘自行移动；否则上身可能反向补偿行驶，引起伸臂、触限或夹持偏载。预先规划相对底盘的上身关节路径，执行时结合实际底盘位姿检查世界空间净空。接近固定放置点时切回世界系目标，并在切换时检查目标连续性。

### 6.2 准入条件与资源归属

每个并行动作声明所用资源：底盘、升降、左臂、右臂、夹爪。一个资源同一时刻只能由一个动作写入。并行调度上身准备时，关闭 `navigate` 内部的上身准备分支，避免两套目标竞争。

准入检查包括：空载或已稳定双手持箱、位于允许区域、当前是直线路段、上身整段路径可达、组合后的箱体和机器人扫掠包络无碰撞。仅证明两个动作单独无碰撞不足以放行并行。

初期持箱转弯时保持上身姿态。进入货垛或交接台最终对位区时结束并行准备；较慢的一组尚未完成时，在预定清空区域等待，禁止带着未完成的上身动作进入狭窄区域。

### 6.3 同步、异常与计算开销

上身以共同的轨迹进度执行升降和双臂指令，尊重各关节速度限制；底盘单独限速，不强迫三组同时到达而突破速度限制。姿态变化幅度大时可降低该路段底盘速度。

预检查失败且尚未执行时，退回既有串行路径。执行中出现路径偏差或净空不足时，协调减速、保持夹持，停止后从实测状态重新规划；出现夹持失效、倾角超限等现有故障时保持停机，不自动继续，更不自动松爪。

优先复用预计算的相对底盘路径，避免每个物理步重新做多种子 IK。缓存必须带起始关节、夹持变换、目标层和路线有效性条件；变化后重算。几何姿态可提前准备，但不对未确认的箱体姿态直接套用旧抓取轨迹。

## 7. 分阶段实施

| 阶段 | 修改范围 | 通过后再推进的条件 |
|---|---|---|
| P0 基线与统计 | 增加各阶段耗时、等待原因、交接锁占用和三组实际运动区间统计 | 当前阈值下完成可比测试；未完成 18 箱则先记录并处理阻塞问题。 |
| P1 空载并行 | 复用 `move_and_prepare`，补齐 B 放箱后返回、A 放箱后返回的收臂与高度预置；增加资源独占和清障门槛 | 单箱取放及返回通过，路线和撤手不碰箱；比较现有已并行段，排除重复收益。 |
| P2 A 持箱并行 | 源垛清出后，直线运箱与交接持箱姿态准备重叠 | 上中下层、两侧取箱均通过，尤其覆盖原中层 IK 失败位置。 |
| P3 B 持箱并行 | 交接台清出后，目标层预备升降与直线运箱重叠 | 上中下层、两侧、中心和边列、同层邻箱有无等分支通过。 |
| P4 流水调度 | 提前外部等待、缩短无必要占锁等待；保持现有库存与提交语义 | 交接拥塞、缺箱和推箱机构参与场景无死锁、漏箱、重复放箱。 |
| P5 连续验收 | 18 箱全流程、日志与全过程视频 | 全部物理完成，最终逐箱复核，性能与稳定性均满足验收。 |

新增开关建议分别控制空载、A 持箱、B 持箱并行，便于逐项对比及回退。开关名称属于待实现设计，不代表当前已可配置。

主要代码落点：`relay_runtime.py` 的 `run_a/run_b`、`dock/navigate/move_and_prepare`、`plan_hands` 与监测记录；`relay_task.py` 只在确有需要时补充调度记录，保留互锁和库存一致性；参数集中放入 `relay_demo_config.json`。

## 8. 验证与收益评估

使用相同初始场景、箱序、物理步长、速度上限、渲染与录像设置对比。建议按“当前基线 → 仅空载并行 → 加 A → 加 B → 调度优化”逐级测试，每级单独归档报告，最终配置至少完成 3 次连续 18 箱测试。

| 指标 | 记录与判断方式 |
|---|---|
| 完成质量 | 18/18 完成、无掉箱、无非预期邻箱碰动，最终位置和姿态满足现有放置检查。 |
| 任务用时 | 总仿真秒数、单箱周期、A/B 各阶段用时，以及交接等待时间。 |
| 实际速度 | 总墙钟时间与实时率（仿真时间/墙钟时间），保证规划开销没有抵消动作收益。 |
| 实际并行 | 分别统计底盘＋升降、底盘＋双臂、三组同时运动时长，以实测速度判定，不能仅看状态机标签。 |
| 稳定性 | A/B 各自最大倾角、接触丢失、关节限位余量、IK 失败和串行回退次数。 |
| 调度 | 每箱锁等待、锁持有时长、空缓冲与满缓冲等待，确认瓶颈实际位于哪台机器人。 |

若一段导航耗时 `Tnav`，姿态准备耗时 `Tprep`，理想可重叠时间上限是 `min(Tnav, Tprep)`；实际还要扣除清障、转弯、同步等待与计算开销。总任务收益由关键路径决定，不能简单把 A、B 的节省时间相加。

以总仿真用时降低 15%～25% 作为首轮评估目标，不作为已验证承诺。若达不到目标，应依据阶段统计调整，而不是删去支撑确认、夹持检查或邻箱放置顺序。若基线无法完成 18 箱，仅报告相同已完成区段的对比，不给出完整任务加速比。

验收资料保存到独立输出目录，包含配置快照、报告、遥测、分阶段时间表及从初始化到完成的仿真视频。故障测试单独标记失败点，不混作成功结果。

## 9. 推荐执行顺序

先建立当前配置基线并完成空载并行，再分别开放 A、B 在开阔直线路段的持箱并行，最后根据等待统计优化交接调度。保留最终取放的接触顺序，把优化集中在可重叠的运输和准备阶段。
