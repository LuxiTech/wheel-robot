# 轮式双臂机器人双机接力拆码垛 Demo 实施方案

日期：2026-09-22。本文保留设计时的方案与验收目标。后续已接入自动调试代码，当前实现、与方案的差异及实际验收状态见 [自动接力说明](RELAY_DEMO.md)；完整接力尚未通过验收。

## 1. 目标与工程基础

Robot A 将源托盘的箱子逐层拆解并送到 handoff 左区 L；推箱机构将箱子从 L 推到右区 R；Robot B 从 R 取箱并逐层码到目标托盘。两机可在各自作业区并行工作，共享交接区由调度器互锁。

沿用当前 `config/relay_config.json`：每层 2 行×3 列，3 层共 18 箱；单箱 400×300×220 mm、1 kg；托盘 1320×820×130 mm；handoff 桌高 750 mm。当前对象是开口周转箱，夹箱沿的抓法不能直接套用到封闭纸箱。

已存在：双机器人/升降/AG95 替代夹爪模型、动态箱垛、双箱位中转桌、物理推板、手动调试与环境验收。尚待实现：自动箱沿抓取、受限空间放置、全身协调、视觉定位流水线与自动接力。

现有 `arm_ik.py` 是给定腰高的单臂求解；`box_perception.py` 是已知箱体几何和支撑面的中心/yaw 拟合，均不能直接视作已完成全身 IK 或通用 6D 位姿估计。已有推板使用仿真位姿作为理想区域传感器，尚无机械臂交接互锁。

## 2. 场地与顺序

布局：源托盘 → A 作业区 → L → 推板 → R → B 作业区 → 目标托盘。配置 A/B 等待位及持箱等待姿态，等待位不得侵入推板、对方机器人或运输通道。

为避免“两个窄边的箱子”对应不清，实施时将每层定义为以下俯视格子；箱子的长边沿 X，三列沿 X，近/远两行沿 Y：

```text
远排     F1    F2    F3
近排     N1    N2    N3
          X →
```

默认将“先两边后中间”解释为先处理外侧两列，再处理中间列，即每层 4 个外侧箱、2 个中间箱，而不是全层只有 2 个外侧箱。候选拆垛顺序：N1、N3、F1、F3、N2、F2；候选码垛顺序：F2、N2、F1、N1、F3、N3。码垛优先远排，为后续操作保留通路。

这些是优先级，不是无条件强制路径。每次执行前检查目标暴露面、双臂可达性、近排遮挡和退爪空间；必要时调整底盘站位或同优先级箱序。若实际几何无法按此顺序操作，记录失败原因并改站位/布局，不执行穿模路线。

拆垛从顶层向下，当前层清空才进入下一层；码垛从底层向上，当前层全部放稳才开始上一层。若现场“两个窄边箱”指其他堆型，只需调整格子映射和优先级配置。

## 3. 动作技能

### 3.1 直接双端夹取

识别箱沿和双侧接近空间 → 底盘停稳/腰部预定位 → 两臂预抓取 → 下探夹沿 → 两侧闭合 → 小幅试提 → 确认无滑移 → 提至脱离垛面 → 收至搬运姿态。

抓取成功不能仅凭夹爪闭合指令完成：需要接触/力或夹爪反馈、箱子随动、相对滑移等证据。全箱离垛前保持双端支撑。

### 3.2 单端提拉再接取另一端

检查可接近的箱沿 → 第一只手夹住并验证 → 保留另一端支撑接触，围绕该支撑做受限倾斜/小幅提拉 → 重新观测另一端暴露情况 → 第二只手进入并夹住 → 双手协调恢复水平 → 试提 → 搬运。

控制目标是形成足够的第二只夹爪插入间隙，不是固定抬高若干厘米。提拉幅度由箱沿、夹爪厚度、邻箱和支撑几何决定，设置最大位移、倾角、受力与超时限制。单端提拉不一定能暴露另一端；若观察到间隙仍不足，应复位或换站位，禁止盲目增加提拉。

在当前 AG95 替代夹爪及 14 mm 箱沿上，先验证夹持接触、指尖可插入性、单端承载和箱体抗倾翻。能力不足时需调整夹具或箱体接触设计，并记录为硬件假设变更。失败时有支撑地放回、松开重试；不得用固定约束或位置瞬移冒充抓取。

### 3.3 放置与推入

空间充足：到预放置位 → 受控下降 → 确认承托接触和卸载 → 松爪 → 沿无碰路径退爪 → 检查放稳。

空间受限：在目标旁可放置且有连续支撑的过渡位落箱 → 卸载/松爪 → 退出夹持姿态 → 切换到箱侧推送姿态 → 沿托盘面或已完成层顶面小幅推入 → 撤手 → 检查最终姿态及邻箱是否移位。

规划前同时检查落箱和退爪路径，不能只检查箱子能否到达目标。上层推入尤其要检查全过程支撑、跨缝和倾翻，不得在无支撑区域悬空推箱。若托盘余量不足以容纳过渡位及退爪空间，需要改变站位、末端结构或提供承托辅助，不能预设必然可推入。

推送采用低速、位移/力限制与视觉反馈；周转箱筋条可能互相卡住，超限即停并复查。每个技能统一返回执行状态、失败原因及箱体状态证据。

## 4. 视觉与全身控制

视觉流程：RGB-D → 2D 实例检测/分割 → 利用箱体模型和深度估计 6D 位姿 → 变换到工位/世界坐标 → 构建箱垛占用和碰撞场景 → 生成抓取/放置候选。紧贴、同色周转箱需区分实例；检测框本身不足以给出箱沿接触点，应进一步利用模型或局部深度定位箱沿。

输出至少包含箱 ID、时间戳、坐标系、位姿、尺寸、置信度和可见性；倾斜提拉后、推箱后、放置后重新观测。对称箱体按等价朝向处理，避免姿态估计跳变引起夹爪旋转。相机、底盘和腰部关节反馈需要时间对齐。

开发第一阶段允许使用仿真真值验证调度与运控，但明确标记 `ground_truth`；最终视觉演示使用相机估计驱动决策，仿真真值仅作独立评价，低置信度触发重新观测而非静默回退。

全身状态为 q=[底盘 x,y,yaw；腰高；左臂关节；右臂关节]。双手持箱时，以箱体轨迹和两手相对于箱体的抓取变换生成双手目标，统一求解全身 IK/QP，并进行轨迹时间参数化和反馈执行。

约束包含双手相对位姿、关节/腰/底盘速度和加速度、碰撞距离、载荷和稳定性。全身运动学本身不能保证力学稳定，需要带载加减速限制及双臂柔顺/受力协调。单端倾斜、双端持箱、放置卸载、推送分别使用不同的接触模式和约束。

运输/接近阶段允许底盘、腰和双臂同步运动；精确抓取、单端提拉和推入阶段首版固定底盘，以腰和双臂协调为主。底层只接受一个协调器的有效运动指令，避免导航与全身控制同时控制底盘。所有执行轨迹共享时间轴；任何关键轴跟踪超差时统一减速/暂停并重新规划。

当前全向底盘可使用平面三自由度模型，最终指令经轮速逆解下发；若换差速底盘，必须加入非完整约束。补齐规划碰撞检测并复核物理自碰撞配置，不能因模型当前关闭内部自碰撞就默认路径可行。

## 5. 双机状态机

A：选箱 → 观测 → 直接抓/单端提拉抓 → 搬到 L 外等待位 → 等待 L 可用 → 申请交接区 → 放 L → 松爪撤离 → 提交交接 → 下一箱。

如果 A 已持箱且 L 仍有箱，进入 HOLD_WAIT，保持稳定持箱姿态；手臂不能伸在 L 上方等推板。正常等待不设“超时后强行放箱”；超过持箱时间阈值进入异常处理，使用经过验证的备用承托位或受控停止。

B：等待 R 箱可取 → 预留目标码垛位 → 申请交接区 → 抓 R → 将持箱及手臂完全撤出 → 提交取走 → 运输 → 直接放/放后推 → 检查放稳 → 下一箱。

R 无箱时 B 在等待位等待；R 有箱但推板未回原点，或箱子仍在运动，也不得抓取。B 抓取失败时不清空 R 的占用、不创建新任务重复领取同一个箱子。

## 6. Handoff 互锁与箱子所有权

首版对整个交接区采用一把互斥锁，所有者只能为 A、B 或 PUSHER；两机在交接区之外仍可并行。简化共享区域互锁有利于验证，后续才按几何分区提升吞吐。

区分“物理占用”和“任务预留”。L/R 状态至少包含 EMPTY、RESERVED、OCCUPIED、UNKNOWN；在途箱用 TRANSFERRING 表示，不能把推送中暂时离开 L 的箱子当成已经完成交接。

| 动作 | 必须同时满足的条件 | 完成后提交 |
|---|---|---|
| A 放 L | L 已确认空、未被他者预留；推板回原点；A 获得锁；进入路径空闲 | 箱子稳定承托、夹爪松开、A 已退出后，L=OCCUPIED，转移箱子所有权，释放锁 |
| 推板 L→R | L 恰有一个稳定箱；R 已确认空；两机和所持箱均退出；推板获得锁 | 原子预留两区，记录在途 ID；真实推送并验证 R 到位；推板退回后提交 L=EMPTY、R=OCCUPIED，释放锁 |
| B 取 R | R 恰有一个稳定箱；推板回原点；B 获得锁；目标任务已预留 | 抓牢、箱子和手臂退出后，R=EMPTY，所有权转给 B，释放锁 |

L/R 都有箱时，优先让 B 清空 R；L 有箱/R 空时，优先推送；L/R 都空时，等待 A。占用未知、观测过期、推板故障时禁止新的交接动作。推送中有障碍进入时暂停并保持锁；确认清空后继续或进入恢复流程，不根据超时自动释放资源。

状态提交使用唯一 action_id/box_id 和幂等确认，避免重复回调导致重复计数。箱子所有权依次为 SOURCE → A → L → PUSHER → R → B → TARGET；逻辑状态和实际观测冲突时停在可恢复状态并复查。

## 7. 建议软件分工

| 模块 | 职责 |
|---|---|
| `relay_perception.py`（新增） | RGB-D 目标识别、6D 位姿、局部箱沿和置信度 |
| `relay_world_state.py`（新增） | 箱 ID、层/格子、物理占用、支撑关系和任务预留 |
| `relay_skills.py`（新增） | 直接抓、提拉接抓、放置、推入、试提和退出 |
| `whole_body_control.py`（新增） | 底盘/腰/双臂联合求解、轨迹和执行反馈 |
| `relay_task.py`（新增） | A/B 状态机、交接锁、所有权和异常恢复 |
| `relay_pusher.py`（扩展） | 增加锁、机械臂退出确认、在途 ID、故障握手 |
| `run_relay_scene.py`（扩展） | 接入双机运行时、状态面板、自动开始/复位和报告 |

先沿用 Isaac Sim 和现有 Python 控制层，不为 demo 强制引入整套 ROS 2。将感知、技能、调度和驱动接口分开，为后续真机适配保留边界。

若后续采用 ROS 2/MoveIt，Task Constructor 可组织抓放阶段及规划场景更新；全身闭链双臂协调、底盘联合执行和力闭环仍需单独实现/验证，不能认为框架安装后自动具备这些能力。

## 8. 实施顺序与验收

| 阶段 | 实施内容 | 放行条件 |
|---|---|---|
| M0 | 站位/可达性、箱沿夹持、托盘放推空间、自碰撞审查 | 证明两类抓取与受限放置在当前几何上可行；不通过先改夹具/布局 |
| M1 | 单机、单箱三类技能，先用真值输入 | 真实接触抓提、承托卸载、连续推入；失败能放回/停止 |
| M2 | 两机、单箱完整交接及等待互锁 | A→L→R→B→目标完成，无争用，无提前清占用 |
| M3 | 一层 6 箱自动拆码垛 | 按外侧优先/中间优先规则完成，邻箱不被挤乱 |
| M4 | 三层 18 箱、全身协调运输 | 顶层向下拆、底层向上码，升降覆盖高度，最终垛稳定 |
| M5 | 接入真实相机估计、连续运行和故障注入 | 视觉闭环完成；指标达标；回放能解释每次转移和失败 |

建议验收门槛（待 M0 标定，不是现有实测能力）：最终中心位置误差 ≤10 mm、水平朝向误差 ≤3°；箱体完全位于目标承托区域且有有效支撑，释放后线速度 <0.02 m/s、角速度 <0.05 rad/s 并连续保持 1 s。上层放置还需验证接触/支撑关系；箱沿抓取的局部误差门槛根据实际插入间隙单独制定，不能直接采用 10 mm。

完整 18 箱流程建议连续成功 3 轮；无掉箱、穿模、非预期碰撞、死锁或丢失/重复箱子。最后完成时重新检查全垛稳定，而非只检查最后一箱。独立测试必须覆盖：L 占用时 A 持箱等待、R 空时 B 等待、R 占用禁止推送、机械臂未撤禁止推送、推板未回禁止入区、抓空/滑移、低置信度、推板堵转及流程中复位。

全身同步单独验收：运输阶段日志中底盘、腰和至少一条手臂的有效运动存在时间重叠，箱体轨迹误差在设定范围内；“同时发指令”不算成功证据。

报告包含每箱经历的状态与策略、耗时、重试、最大跟踪误差、放置误差、等待时间、异常和总完成数。GUI 展示 A/B 状态、L/R 占用、推板状态、锁持有者、当前箱 ID、抓放策略与完成进度。输出录像和 JSON 报告；初始化和复位可设置箱位，任务执行中箱子必须依靠接触动力学移动。
